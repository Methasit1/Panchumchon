
## ตั้งค่า Supabase

1. สร้าง project ใน Supabase แล้วรัน SQL ตามลำดับ:
   `supabase_tables.sql` → `supabase_policies.sql` → `supabase_doc_types.sql` → `supabase_storage.sql`
2. สร้าง auth user สำหรับพี่เอ็มใน **Authentication → Users** (ใช้ email/password)
3. เพิ่มแถวใน `user_account` ด้วย `user_id` = id ของ auth user, `username`, `display_name`
   และ `role_id` ของแถว `ADMIN` ในตาราง `role` (ต้อง `is_active = true`)
   — ไม่มีไฟล์ seed บัญชีตามที่ตกลงกัน
4. คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ URL และ anon key ของ project

```bash
cp .env.example .env.local
npm install
npm run dev
```

`.env.local` ถูก `.gitignore` อยู่แล้ว ห้าม commit

- RLS เดิมยังปิดข้อมูล งบ/หน่วยงาน/เอกสารแนบ/audit ไม่ให้ประชาชน รอคำยืนยันข้อ 5.1

### ข้อตกลงที่ใช้ในหน้านี้

- งบประมาณรวม **นับทุกสถานะ** รวมโครงการที่ยกเลิก
- ไม่ใช้เปอร์เซ็นต์ความคืบหน้าแล้ว (ประเมินยาก) — สถานะโครงการเป็นตัวชี้วัดหลัก
- สีสถานะ "ยกเลิก" ใช้สีเทาตามดีไซน์ (เอกสารยังไม่กำหนด — ข้อ 18.2)
- ตัดฟิลด์ผู้ใหญ่บ้าน/ตำบล/อำเภอ/จังหวัดออก เพราะยังไม่มีคอลัมน์ในตาราง `village`
- ตัวกรองพื้นที่ใช้ปุ่ม "ทั้งหมด" + dropdown "เลือกหมู่บ้าน" (ยังไม่มีข้อมูลระดับตำบลให้ cascade)

## ทดสอบหน้าจัดการโครงการ (F06)

เปิด `http://localhost:5173/admin/projects` (หรือกดเมนู "จัดการโครงการ")

- ถ้าไม่มีข้อมูลเลย → เห็น empty state และปุ่ม "สร้างโครงการใหม่"
- **สร้างโครงการ**: modal บังคับ หมู่บ้าน / ชื่อ / ประเภท / สถานะสิ่งก่อสร้าง / วัตถุประสงค์ / ปีแผน
  - รหัสสร้างอัตโนมัติ `INF-<ปี 2 หลัก><ลำดับ 3 หลัก>` จากตาราง `project_code_counter` (BR-05)
  - ถ้ารหัสชนกันจะสร้างใหม่แล้วลองอีกครั้งหนึ่ง
  - ถ้ายังไม่มีหมู่บ้านหรือประเภทในระบบ ปุ่ม "สร้างโครงการ" จะถูกปิดและขึ้นคำเตือน
- **เริ่มดำเนินการ**: ระบบตรวจ BR-08 ถึง BR-11 ก่อน
  - ไม่ครบ → dialog แสดงรายการที่ขาด + ปุ่มไปหน้าฟอร์ม (`/admin/projects/:id` ยังเป็น placeholder)
  - ครบ → ยืนยันแล้วเปลี่ยนเป็น `IN_PROGRESS` ความคืบหน้า 1% และบันทึก `actual_start`
- **เสร็จสิ้นโครงการ**: ยืนยันแล้วเป็น `COMPLETED` 100% และบันทึก `actual_end`
- **ยกเลิก**: ต้องกรอกเหตุผล (BR-20) สถานะเป็น `CANCELLED` และคง % เดิม (BR-22)
- **ลบ**: soft delete (`is_deleted = true`) เฉพาะสถานะรออนุมัติ (BR-18)
- สถานะเสร็จสิ้น/ยกเลิกจะถูกล็อก ไม่มีปุ่มแก้ไข
- การ์ดที่ `actual_end` หลัง `planned_end` จะขึ้นป้ายแดง "เสร็จสิ้นล่าช้า"

### ข้อตกลงที่ใช้ในหน้านี้

- ใช้การ์ดตาม Figma แทนตารางสรุปใน Proposal ข้อ 12
- เพิ่มช่อง **ปีแผน (พ.ศ.)** ใน modal (Figma ไม่มี แต่ BR-27 บังคับ) ค่าเริ่มต้น = ปีปัจจุบัน
- "สถานะสิ่งก่อสร้าง" เป็น dropdown 5 ค่า ตาม check constraint ของ DB
  (`ใช้งานได้ปกติ / ชำรุด / อยู่ระหว่างซ่อม / เลิกใช้งาน / ก่อสร้างใหม่`)
- ข้อความใต้ชื่อโครงการเป็นข้อความคงที่ตามสถานะ (ยังไม่ผูก `project_note`)
- ไม่มีคอลัมน์ผู้อนุมัติยกเลิก → แสดงเฉพาะเหตุผล
- หน้านี้ใช้ปีงบประมาณปัจจุบัน ยังไม่มี dropdown เลือกปี
- ปุ่ม "การจัดการ" เป็น dropdown มี "ดูรายละเอียด", "แก้ไขโครงการ", "ยกเลิกโครงการ", "ลบโครงการ"
  (ดูรายละเอียดเปิดฟอร์มในโหมดอ่านอย่างเดียว `?mode=view`)

## ทดสอบหน้าหมู่บ้าน (F01)

เปิด `http://localhost:5173/admin/villages` (หรือกดเมนู "หมู่บ้าน")

- การ์ดแต่ละใบแสดง **ชื่อหมู่บ้าน + หมู่ที่** และ **จำนวนโครงการ**
- **เพิ่มหมู่บ้าน**: modal ตามดีไซน์ Figma — ชื่อหมู่บ้าน* และหมู่ที่* (รับเฉพาะตัวเลข)
  - ใส่หรือไม่ใส่คำว่า "บ้าน" ก็ได้ ระบบตัดคำว่า "บ้าน" ออกตอนบันทึก แล้วเติมกลับตอนแสดงผล
  - ชื่อหมู่บ้าน + หมู่ที่ซ้ำกับที่มีอยู่ → ขึ้นข้อความ *"ชื่อหมู่บ้านและหมู่ที่นี้มีอยู่แล้ว"* (BR-02)
  - ตรวจซ้ำโดยเทียบชื่อแบบตัด "บ้าน" แล้ว จึงกันเคส "หลวง" กับ "บ้านหลวง" ได้
  - บันทึกสำเร็จจะเห็นการ์ดใหม่ทันที
- **การจัดการ**: เปิด modal เดียวกันในโหมดแก้ไข พร้อมสวิตช์ "เปิดใช้งานหมู่บ้านนี้"
- หมู่บ้านที่ปิดใช้งานจะแสดงการ์ดจาง + ป้าย "ปิดใช้งาน" และยังกดจัดการได้
- ไม่มีปุ่มลบหมู่บ้าน — ใช้การปิดใช้งานแทน (BR-26) เพราะโครงการอ้างอิงหมู่บ้านอยู่

### ข้อตกลงที่ใช้ในหน้านี้

- จำนวนโครงการบนการ์ดนับ **ทุกปีแผน** ที่ `is_deleted = false` (ต่างจากแดชบอร์ดที่นับเฉพาะปีที่เลือก)
- หมู่บ้านที่ปิดใช้งานยังอยู่ในรายการ (เพื่อให้เปิดกลับได้) แต่ไม่ถูกเลือกในฟอร์มสร้างโครงการ
- ลำดับการ์ด: หมู่บ้านที่เปิดใช้งานก่อน แล้วเรียงตามหมู่ที่
- หน้านี้ไม่มีตัวกรอง/ค้นหา (ตามดีไซน์)

รายละเอียด:

- การ์ดสรุป 3 ใบด้านบนแสดงจำนวนตัวเลือกของแต่ละชนิด และกดเพื่อสลับแท็บได้
- การ์ดตัวเลือกแสดงชื่อ + จำนวนโครงการที่อ้างถึง + ปุ่ม "การจัดการ"
- **เพิ่มตัวเลือก**: modal ช่องเดียว (ชื่อห้ามซ้ำกับที่มีอยู่)
- **การจัดการ**: เปลี่ยนชื่อ หรือปิด/เปิดใช้งาน
- ตัวเลือกที่ปิดใช้งานจะจาง + ป้าย "ปิดใช้งาน" และไม่แสดงในฟอร์มสร้างโครงการ
- ไม่มีปุ่มลบ เพราะ `supabase_policies.sql` revoke สิทธิ์ DELETE บนตารางข้อมูลพื้นฐานไว้ (BR-26)

### ข้อตกลงที่ใช้ในหน้านี้

- ตัวเลขบนการ์ดสรุป = จำนวนตัวเลือกทั้งหมด (นับที่ปิดใช้งานด้วย)
- จำนวนโครงการบนการ์ด = โครงการที่ยังไม่ถูกลบ นับทุกปีแผน
  (หน่วยงานนับจาก `project_agency`, แหล่งเงินนับจาก `project_location_budget`)
- ตัวเลือกที่เพิ่มใหม่จะไปปรากฏในฟอร์มสร้างโครงการทันที (เฉพาะที่ `is_active = true`)
- หน้าเว็บไม่มีฟังก์ชันลบข้อมูลพื้นฐาน — ใช้ปิดใช้งานแทน (BR-26)

## โหมดมืด/สว่าง

- ปุ่มสลับอยู่ที่ header ทั้งฝั่ง `/admin` และ `/public` (ไอคอนพระจันทร์ = โหมดสว่าง,
  ดวงอาทิตย์ = โหมดมืด)
- ค่าที่เลือกเก็บใน `localStorage` key `panchumchon-theme` (`light`/`dark`) และ
  ใส่ class `dark` ที่ `<html>` ตอนโหลด (กันกระพริบ)
- ค่าเริ่มต้น = โหมดสว่าง (ไม่อ่าน `prefers-color-scheme`)
- Tailwind v4 ใช้ `@custom-variant dark` ใน `src/assets/main.css` + CSS variables
  (`--bg-page`, `--bg-card`, `--bg-hover`, `--bg-active`, `--text-primary`,
  `--text-secondary`, `--text-muted`, `--border`, `--border-soft`)
- สีที่ใช้ซ้ำทั่วแอปถูก override ผ่าน CSS selectors ภายใต้ `.dark` (bg-white,
  bg-[#F8FAFC], text-[#181C1B], border-[#BFC9C3] ฯลฯ) ทำให้ไม่ต้องแก้ทุก component
- จุดที่ยังเป็น light เท่านั้น: โลโก้/รูปภาพ (ไม่จำเป็น), badge สีสถานะ (ตั้งใจให้สีคงที่)

## งานที่ต้องทำต่อ

1. **ประวัติ/Audit** (`/admin/history`) — ตาราง `audit_log` ยังไม่ถูกเขียนจากหน้าเว็บ (BR-25)
2. **ฝั่งประชาชน** — ทุกเส้นทางยังเป็น placeholder (F08)
3. ตัวกรองปีงบประมาณในหน้าจัดการโครงการ (ตอนนี้ใช้ปีปัจจุบัน)
4. ผูกข้อความใต้ชื่อโครงการจากการ์ดให้ดึง `project_note` ล่าสุด (ถ้าต้องการ)
5. ตรวจสอบ BR-23/BR-24 การล็อกข้อมูลหลังเสร็จสิ้น/ยกเลิก (ทำแล้วระดับ UI)
6. seed ข้อมูลพื้นฐาน `doc_type` (ปร.4, ปร.5, เอกสารอื่นๆ, ภาพถ่ายก่อน/หลังทำ) ใน Supabase



## เรื่องที่รอยืนยัน (ข้อ 18)

- ยกเลิก/ลบ: การแสดงโครงการยกเลิกต่อประชาชน (BR-22 กับข้อ 18.1.2 ยังขัดกัน), การแก้ไขข้อมูลที่ลงผิด
- สถานะ: มีสถานะอื่นนอกจาก 3 สถานะหลักหรือไม่ (รวมสีของสถานะยกเลิก)
- ข้อมูล: รายการ Dropdown ทั้งหมด, ประเภทเอกสารบังคับ, รูปแบบรหัส INF-69001 (ไม่มี function รันรหัส), ตัวเลขงบที่เปิดเผย
- หน้าประชาชน: ฟิลด์ที่แสดงในหน้ารายละเอียด
- ระบบ: การสำรองข้อมูลและกู้รหัสผ่านผู้ดูแล
- หมู่บ้าน: จำนวนโครงการต่อหมู่บ้าน, ข้อมูลตำบล/อำเภอ/จังหวัด
- จุดที่เอกสารยังไม่ระบุ: F07 และ BR-16 (ข้ามไปในตาราง)
- เพิ่มจากหน้าจัดการโครงการ: เกณฑ์ "เสร็จสิ้นล่าช้า" (ใช้ `actual_end > planned_end`),
  ไม่มีคอลัมน์ผู้อนุมัติยกเลิก, การแก้ไขโครงการหลังเริ่มแล้วทำได้แค่ไหน (ตอนนี้ยังไม่เปิดให้แก้)
